A fix for `oxp3-tool kernel keep` on CachyOS with Limine.

## Fixed

- `kernel keep` now makes the kernel running now the one every power-on boots. Before, after a kernel booted once from `kernel try`, it could say that every power-on boots the stock kernel ("Limine has not recorded booting it") and then print `Done`.
  - The cause: Limine 12.9.5 moved its record of the last booted entry (the UEFI variable `LimineLastBootedEntry`) to a new vendor GUID, and Limine no longer reads the old one. oxp3-tool still read the old variable, which an older Limine had last written for the stock kernel. It now reads the variable of the Limine version that boots next (found from the EFI binary on the ESP, or else from this boot's `LoaderInfo`).
  - When that variable names another entry or none (for example after a Limine update, or when the firmware lost Limine's write), `keep` writes the running kernel's entry to it, in the same format Limine uses, and reads it back. With `remember_last_entry` off, it points `default_entry` at the running kernel's entry instead, with a comment above that line recording the old value.
  - `keep` refuses, and changes nothing, when it cannot make the running kernel the default: the running kernel is no longer installed, its entry's files are missing or changed, or it has several entries and Limine did not record which one booted. It prints `Done` only once it has checked that Limine boots the running kernel, and the message names that kernel.
- With `timeout: no` in limine.conf, `oxp3-tool kernel` now says Limine waits in its menu at power-on (it does, whatever entry it has selected), and `kernel keep` refuses instead of claiming a kernel boots.
- With `remember_last_entry` off, going back to a kernel whose `default_entry` line `keep` had replaced puts that line back and removes the comment, and `oxp3-tool kernel` warns not to remove the kernel `default_entry` points at.

## Install

In Desktop Mode, open Konsole and run:

```bash
curl -fsSL https://raw.githubusercontent.com/Featherwolf/OXP3-Tool-for-Bazzite/HEAD/get.sh | sudo bash
```

Or download `oxp3-tool` below, check it against `oxp3-tool.sha256`, and run it with `sudo python3 oxp3-tool`. Updates of the [OXP3 Deck](https://github.com/Featherwolf/OXP3Deck) Decky plugin ask for this version or later.
