`status` now says when variable refresh (VRR) is safe to turn on, and `status --json` reports it for the OXP3 Deck plugin.

## New

- On a kernel with the display fix (7.2.10 or later, which has the `xe.enable_dc_balance` parameter and leaves it off), `status` adds a tip: variable refresh (VRR) is safe on this kernel, with where to turn it on in Game Mode (Steam: Settings > Display > Enable VRR, where Steam offers it). When the panel reports its variable-refresh range, the tip also says the lowest frame rate to keep a frame limit at. In Desktop Mode, it says Adaptive sync can be set to Automatic.
- `status` shows the panel's variable-refresh range when the kernel reports it.
- `status --json`: `refresh` gains `vrr_safe` (true, false, or null when it cannot be told), `vrr_reason` (a short code: `fixed`, `predates`, `bug`, `param_on`, `old_firmware`, `firmware_unknown`, `no_firmware` or `xe_not_loaded`), `vrr_why` (the reason in words) and `vrr_range_hz` ([min, max] or null).

Nothing changes on older kernels: the existing warning to leave VRR off before 7.2.10 stays as it was.

## Install

In Desktop Mode, open Konsole and run:

```bash
curl -fsSL https://raw.githubusercontent.com/Featherwolf/OXP3-Tool-for-Bazzite/HEAD/get.sh | sudo bash
```

Or download `oxp3-tool` below, check it against `oxp3-tool.sha256`, and run it with `sudo python3 oxp3-tool`. The [OXP3 Deck](https://github.com/Featherwolf/OXP3Deck) Decky plugin 0.5.0 shows the VRR row in Quick Access → Power and on its Fixes tab.
