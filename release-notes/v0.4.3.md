A new optional fix, `speaker-profile`, that makes the built-in speakers louder without clipping.

## New

- `speaker-profile` (optional; `sudo oxp3-tool apply speaker-profile`): a PipeWire filter, *OXP3 Speakers*, that only the built-in speaker output passes through. It is in `/etc/pipewire/pipewire.conf.d/80-oxp3-speaker-profile.conf`, so it works for every user in Game Mode and in Desktop Mode.
  - The filter chain: a 4th-order high-pass at 180 Hz; +2 dB at 300 Hz, +2.5 dB at 3 kHz and +2 dB from 8 kHz; +8 dB of gain; and a 13 ms look-ahead peak limiter (-1.5 dBFS) with a hard ceiling at -0.3 dBFS. It uses only PipeWire's builtin filters (PipeWire 1.4 or newer), so no packages are needed. PipeWire has no builtin limiter, so the limiter is built from its `abs`, `max`, `delay`, `bq_lowpass`, `recip` and `mult` filters, in a way that works the same at any sample rate from 44.1 to 192 kHz and with PipeWire 1.4's two-input `max`.
  - Routing: WirePlumber's smart-filter policy (0.5 or newer) puts the filter in front of the speaker sink. The speaker stays the default output, and Steam's and KDE's volume still control it. Headphones, HDMI and Bluetooth bypass the filter.
  - Apply and revert restart PipeWire for each logged-in user, and sound stops for a moment. With `--no-restart`, log out and back in instead.
  - `status` shows the following:
    - whether each user's PipeWire loaded the profile and whether the speakers go through it (read from `pw-dump`);
    - a warning when the speaker volume is above 100% (software gain that clips);
    - a warning when *OXP3 Speakers* was chosen as the output (there is no sound with headphones then);
    - a warning when a file in `~/.config/pipewire/pipewire.conf.d` replaces the profile, or another speaker filter-chain would stack with it;
    - a warning when the speaker output is named differently from the one the profile was installed for (apply it again).

  `status` suggests the fix when the speaker volume is above 100%.
- `status` has a new group, "Sound fixes".

The profile has not been tested on an OXP3 yet: its values come from modelling the filters, not from measuring the speakers. Please report how it sounds, with the output of `sudo oxp3-tool status` and `pw-link -l` while something plays.

## Install

In Desktop Mode, open Konsole and run:

```bash
curl -fsSL https://raw.githubusercontent.com/Featherwolf/OXP3-Tool-for-Bazzite/HEAD/get.sh | sudo bash
```

Or download `oxp3-tool` below, check it against `oxp3-tool.sha256`, and run it with `sudo python3 oxp3-tool`. The [OXP3 Deck](https://github.com/Featherwolf/OXP3Deck) Decky plugin shows the new fix on its Fixes tab.
